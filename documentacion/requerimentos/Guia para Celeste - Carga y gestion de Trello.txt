OBJETIVO

Ordenar el tablero de Trello para que el equipo pueda trabajar siguiendo el documento de requisitos del proyecto.
El PDF funciona como documento base aprobado. Trello se usa para gestionar el trabajo diario, nuevas tareas, responsables, estados y seguimiento.


1. LISTAS RECOMENDADAS EN TRELLO

Se recomienda usar estas listas:

1. Backlog
   Tareas futuras, ideas, funcionalidades que todavia no se van a desarrollar o que requieren definicion.

2. Analisis / Refinamiento
   Tareas que necesitan aclararse antes de pasar a desarrollo.

3. To Do
   Tareas listas para empezar.

4. Doing
   Tareas que alguien esta trabajando actualmente.

5. Review
   Tareas terminadas por quien las hizo, pero que necesitan revision del equipo, QA o Product Owner.

6. Testing
   Tareas listas para probar funcionalmente.

7. Done
   Tareas terminadas, revisadas y aceptadas.


2. COMO ORDENAR EL TRELLO ACTUAL

El tablero actual ya tiene listas utiles: To Do, Doing, Done, Backlog y Review.
No hace falta borrar todo. La idea es reordenar y sumar tarjetas siguiendo el PDF.

Sugerencia:

- Mantener Done con lo que ya esta terminado.
- Mantener Backlog para funcionalidades futuras.
- Mantener To Do para tareas proximas.
- Mantener Doing para tareas en curso.
- Mantener Review para tareas que deben ser revisadas.
- Agregar Testing si el equipo quiere separar revision tecnica de prueba funcional.

7. COMO USAR CADA TARJETA

Cada tarjeta deberia tener:

- Titulo claro.
- Responsable.
- Descripcion.
- Criterios de aceptacion.
- Checklist si la tarea es grande.
- Comentarios con decisiones importantes.
- Adjuntos si corresponde: capturas, links, archivos o referencia al PDF.

Ejemplo de checklist para ABM de productos:

- Crear formulario de alta.
- Crear listado de productos.
- Crear edicion de producto.
- Crear activacion/desactivacion.
- Validar campos obligatorios.
- Guardar imagen o ruta de imagen.
- Mostrar productos activos en catalogo.
- Probar flujo completo.


8. CUANDO ACTUALIZAR EL PDF Y CUANDO SOLO TRELLO

No hace falta actualizar el PDF por cada tarea nueva.

Actualizar Trello es suficiente cuando:

- Se agrega una tarea tecnica.
- Se divide una tarea grande en subtareas.
- Se cambia un responsable.
- Se mueve una tarea de estado.
- Aparece una mejora menor.
- Se detecta un bug o ajuste puntual.
- Se suman tareas de diseno, testing o implementacion.

Actualizar el PDF solo cuando cambie algo importante del proyecto, por ejemplo:

- Cambia el alcance del MVP.
- Se agrega o elimina una funcionalidad principal.
- Cambian reglas de negocio.
- Cambian roles del equipo.
- Cambian tecnologias base.
- El cliente aprueba o rechaza una decision importante.
- Se modifica un requerimiento funcional ya documentado.

Recomendacion:
El PDF debe quedar como documento formal de base.
Trello debe ser la herramienta viva de trabajo.
Si aparece algo nuevo, primero se carga en Trello.
Si despues esa novedad cambia el alcance o los requisitos, recien ahi se actualiza el PDF.
